# crafty_backup_config

Manage an existing backup policy, including the default policy, using a token
with server BACKUP permission. Crafty's creation API does not return the new ID,
so this resource requires a policy that already exists.

```terraform
resource "crafty_backup_config" "daily" {
  server_id     = crafty_minecraft_server.example.id
  backup_id     = var.existing_backup_id
  max_backups   = 7
  compress      = true
  shutdown      = false
  excluded_dirs = ["logs", "cache"]
}
```

## Schema

### Required

- `backup_id` (String) ID of the existing backup policy to manage.
- `server_id` (String) Crafty server ID.

### Optional

- `after` (String) Server command sent after a backup; empty disables it.
- `backup_location` (String) Backup directory on the Crafty host, using forward slashes. Changing it does not move archives. Requires a superuser.
- `before` (String) Server command sent before a backup; empty disables it.
- `compress` (Boolean) Whether to compress backups.
- `excluded_dirs` (Set of String) Directory exclusions interpreted by Crafty; entries cannot contain commas.
- `max_backups` (Number) Maximum retained backups; zero disables automatic pruning.
- `name` (String) Backup policy name, at least three characters.
- `shutdown` (Boolean) Whether Crafty stops the server while taking a backup.

### Read-Only

- `id` (String) Managed backup policy ID.



Only explicitly configured settings are updated. Omitted settings adopt current
Crafty values; removing a setting from configuration stops enforcing it.
Changing `backup_location` requires a superuser and does not move existing archives.

Refresh never runs or restores a backup. Missing policies and API errors preserve
state and report an error. Destroy only stops managing the policy; it preserves
its settings, associated schedules and archives.
